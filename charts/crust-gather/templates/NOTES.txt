crust-gather installed a one-shot Job:
  {{ include "crust-gather.fullname" . }}

On install it only runs `crust-gather` in Kubernetes, which is typically used here to collect a snapshot and push it to OCI.

The chart will render `collect --reference=...` automatically when `reference` is set.
When `ca_file` is also set, the chart will create a Secret, mount it into the Job,
and add `--ca-file=/etc/crust-gather/ca/ca.pem` to that generated command.

Example install:
  helm install {{ .Release.Name }} {{ .Chart.Name }} \
    --namespace {{ .Release.Namespace }} \
    --set reference=ttl.sh/my-cluster-snapshot:1h

Example install with chart-managed auth secret:
  helm install {{ .Release.Name }} {{ .Chart.Name }} \
    --namespace {{ .Release.Namespace }} \
    --set reference=ttl.sh/my-cluster-snapshot:1h \
    --set username=my-user \
    --set password=my-password

Example install with token auth:
  helm install {{ .Release.Name }} {{ .Chart.Name }} \
    --namespace {{ .Release.Namespace }} \
    --set reference=ttl.sh/my-cluster-snapshot:1h \
    --set token=token-value

Example install with custom CA path:
  helm install {{ .Release.Name }} {{ .Chart.Name }} \
    --namespace {{ .Release.Namespace }} \
    --set reference=ttl.sh/my-cluster-snapshot:1h \
    --set-file ca_file=/path/to/registry-ca.pem

If your registry needs other custom TLS settings, continue to use `job.args` or `collect`
for flags such as `--insecure`.
